# Персональный фитнес-мотиватор

Изолированный Telegram-бот на Python и aiogram 3 для цели «10 тренировок за 30 дней».
Текущая программа рассчитана на женщину с тренировочным опытом, которая возвращается
после годового перерыва: снижение жировой массы, укрепление и постепенный возврат мышечной
формы без использования веса тела в расчётах.
Основная логика не зависит от LLM: onboarding, расписание, напоминания, переносы, тренировки,
прогресс и достижения работают полностью офлайн (кроме Telegram API).

## Что реализовано

- onboarding: имя, дни, время, частота, место, цель и опыт;
- одно напоминание за 2 часа и максимум одно за 10 минут после подтверждения;
- в 09:00 по местному времени тренировочного дня — одно спокойное мотивирующее
  сообщение без кнопок и давления;
- ответы «Да, иду», «Перенести», «Сегодня пропущу» без негативных сообщений;
- ручной перенос или быстрый перенос на 1–2 дня;
- три полноценных дня full-body v4 с приоритетом ягодиц и бёдер и поддерживающей
  нагрузкой на верх тела в каждом микроцикле;
- перед каждой тренировкой выбор 8–10 минут кардио: дорожка, эллипс или велотренажёр;
- после кардио сразу идёт силовой блок из пяти упражнений, заминки нет; общая
  продолжительность тренировки — 50–60 минут;
- румынская тяга и ягодичный мост заменены на тренажёры: сгибание ног сидя,
  отведение ноги назад, разгибание ног, сведение и разведение бёдер;
- первые шесть завершённых тренировок — по два рабочих подхода, затем по три;
- полный план комплекса перед началом тренировки;
- отдельная вручную утверждённая карточка в едином образе девушки и подробная техника
  для каждого упражнения: исходное положение, конечное положение, движение, дыхание,
  ориентиры и частые ошибки; для кардио используется одна понятная фотография;
- после каждого подхода автоматически запускается фиксированный для упражнения отдых:
  60, 75, 90 или 120 секунд;
- упражнение можно заменить готовой альтернативой или пропустить без штрафа;
- для жима ногами готовой альтернативой служит гакк-присед, а не присед с гантелью;
- для жима от груди готовой альтернативой служит сведение рук в тренажёре, а не жим
  гантелей лёжа;
- действие «Дискомфорт / боль» немедленно завершает текущее упражнение без выдуманных
  подходов; после тренировки сохраняется общая оценка нагрузки;
- вес и повторения сохраняются отдельно для каждого подхода, рядом показывается
  предыдущий рабочий вес;
- активная тренировка продолжается с сохранённого шага после перезапуска;
- Telegram `file_id` изображений кэшируется после первой отправки;
- прогресс месяца, общая статистика, серия и достижения 3/5/10;
- пауза на 7 дней, отключение напоминаний, изменение расписания;
- короткие задания по питанию без КБЖУ;
- `/status` для администратора;
- сменные LLM-провайдеры `template`, `groq`, `openrouter`, `ollama`, `openai`;
- медицинский safety-ответ по правилам до обращения к LLM;
- SQLite WAL, история диалога (последние 50 сообщений), whitelist Telegram ID;
- отдельный systemd unit и read-only аудит VPS.

## Архитектура

```text
Telegram / aiogram handlers
        ↓
User · Workout · Progress · Reminder services
        ↓
SQLite (единственный источник состояния)
        ↓
LLM adapter (необязательный дополнительный слой)
        ├── Groq / OpenRouter / OpenAI-compatible
        ├── Ollama
        └── Template fallback
```

APScheduler не является хранилищем расписания. Он запускает короткий scanner, а все будущие
напоминания находятся в SQLite. После перезапуска scanner продолжает работу с той же БД.
Для MVP схема создаётся через SQLAlchemy `create_all`, версия схемы хранится в
`PRAGMA user_version=3`. Обновление с v1/v2 аддитивное: старые активные занятия можно
закончить, а новые получают версионные шаблоны без заминки. Alembic разумно добавить
перед следующей миграцией, изменяющей существующие столбцы.

Сравнение LLM и обоснование выбора: [docs/LLM_RESEARCH.md](docs/LLM_RESEARCH.md).

## Локальный запуск

Требуется Python 3.10–3.14.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# Заполнить .env локально, не присылать токены в чат.
.venv/bin/python -m app.main
```

Для полностью автономного режима оставить:

```dotenv
LLM_PROVIDER=template
LLM_API_KEY=
```

После проверки Groq API с VPS:

```dotenv
LLM_PROVIDER=groq
LLM_MODEL=openai/gpt-oss-20b
LLM_API_KEY=<локально сохранённый ключ>
```

Обязательно задать `ALLOWED_TELEGRAM_IDS` (ID жены) и `ADMIN_TELEGRAM_ID`. Если whitelist
пуст, бот принимает любого пользователя, который знает его username.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

Автотесты покрывают создание расписания, перенос/пропуск, доставку напоминания ровно один
раз, выбор кардио, пошаговый ввод веса и повторений, фиксированный автоматический отдых,
лёгкий режим, немедленную остановку при дискомфорте, план без заминки, карточки техники,
10/10 и достижения, персистентность SQLite, отказ сети/LLM и medical safety fallback.

## Безопасное развёртывание на VPS

Сначала только read-only аудит и снимок работающих сервисов:

```bash
chmod +x deploy/*.sh
sudo ./deploy/audit_vps.sh | tee /tmp/fitness-bot-vps-audit.txt
sudo ./deploy/snapshot_services.sh /tmp/services-before-fitness-bot.txt
```

До установки локальной LLM отдельно оценить свободную RAM, CPU, load average и диск из
этого отчёта. Скрипт установки Ollama намеренно отсутствует: модель нельзя скачивать до
такого решения.

Подготовить environment-файл **на VPS** с правами `0640`, не передавая секреты через чат.
Затем из загруженной директории проекта:

```bash
sudo ./deploy/install.sh . /root/fitness-bot.env
sudo ./deploy/verify.sh
sudo ./deploy/compare_services.sh /tmp/services-before-fitness-bot.txt
```

Установка создаёт только:

- системного пользователя и группу `fitnessbot`;
- код и virtualenv в `/opt/fitness-bot`;
- секреты в `/etc/fitness-bot/fitness-bot.env` (`root:fitnessbot`, `0640`);
- SQLite в `/var/lib/fitness-bot/fitness_bot.sqlite3`;
- unit `/etc/systemd/system/fitness-bot.service`;
- журналы в отдельном journal namespace по unit `fitness-bot.service`.

Скрипт не вызывает `apt`, не меняет глобальный Python, не останавливает и не перезапускает
другие сервисы. Если модуль `venv` отсутствует, установка завершится до запуска unit и
потребует отдельного согласованного решения.

Unit запускается с низким приоритетом и отдельными лимитами: не более 50% одного CPU,
`MemoryHigh=192M`, жёсткий `MemoryMax=256M`, максимум 64 задачи и пониженный вес I/O.
При превышении лимита останавливается только `fitness-bot.service`, а не соседние сервисы.

## Управление сервисом

```bash
sudo systemctl start fitness-bot
sudo systemctl stop fitness-bot
sudo systemctl restart fitness-bot
sudo systemctl status fitness-bot --no-pager
sudo journalctl -u fitness-bot -f
```

`Restart=always`, `RestartSec=5`, `WantedBy=multi-user.target`: после успешного `enable`
бот должен автоматически запуститься после reboot.

## Live-проверка после деплоя

1. В Telegram пройти `/start` и весь onboarding.
2. Проверить меню, «Мой прогресс», паузу и изменение расписания.
3. Временно создать ближайшее напоминание либо дождаться расписания; проверить три ответа.
4. Начать тренировку, выбрать дорожку/эллипс/велотренажёр, проверить полный план без
   заминки, иллюстрации, подходы, таймер отдыха, замену и оценку нагрузки, затем завершить.
5. Перезапустить только `fitness-bot.service`; убедиться, что сессия и SQLite сохранились.
6. Убрать `LLM_API_KEY`/поставить `LLM_PROVIDER=template`, перезапустить новый unit и
   проверить свободный диалог и все основные кнопки.
7. Вернуть Groq, проверить synthetic-сообщение без персональных данных и `/status`.
8. Сравнить running services с baseline; список «no longer running» должен быть пуст.
9. Только после этих шагов выполнить согласованный reboot VPS и проверить `is-active`,
   journal, Telegram `/status` и повторное сравнение сервисов.

Фактический Telegram smoke требует настоящего bot token и действий пользователя в чате;
результаты нельзя считать подтверждёнными по одним unit-тестам.
